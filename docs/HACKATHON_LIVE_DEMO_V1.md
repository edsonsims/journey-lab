# Journey Lab · three-minute live demo script

Script draft · 3 November 2026 · English · **384 spoken words** · **180-second picture plan**.

This is stage 1: a Home-first walkthrough script. The next deliverable is the raw app walkthrough; the final stage adds Edson's ElevenLabs v4 narration, captions and the finished edit. Timings below are editorial targets, not measured audio timings.

The story is **Home → how it works → persona and mission → journey and finding → design and code → paired retest → value**. The app remains the visual focus. Retained agent recordings and completed candidates supply the evidence inside the live walkthrough.

## ElevenLabs production direction

- **Model:** Eleven v4, `eleven_v4`; requested existing voice: **edson**. Resolve the exact account voice ID at the audio stage. No voice ID or audio generation is claimed in this draft.
- **Delivery:** Edson explaining his own product to a judge. Natural, engaged and confident. Preserve the voice's normal accent. Keep the opening welcoming, the observed problem precise and the result assured.
- **Pace:** roughly 140–150 words per minute while speaking, with room for short breaths and the visible interactions. Aim to finish the closing line around 2:58. Adjust picture holds to the measured take rather than stretching words to arbitrary chapter boundaries.
- **Text:** use only the narration paragraphs, with short sentences and paragraph breaks. Amounts and model version are written as spoken words. Do not send screen directions, timestamps or Markdown to the speech endpoint.
- **Pauses:** natural punctuation; no SSML break tags. Avoid long ellipses, artificial sound effects and theatrical emotional tags. Test pronunciation of Journey Lab, Gather and each Muse name in Edson's voice before the full take.
- **Consistency:** prefer one continuous take for these approximately 2,500 characters, retaining sentence boundaries for later alignment. If a line needs replacement, match voice, settings and surrounding context.
- **Mix:** clear foreground voice, app audio muted. The raw demo has no generated narration. Music, if added in the final edit, must remain secondary to spoken evidence.
- **Timing:** the 180-second schedule is not an audio-duration guarantee. Measure the real ElevenLabs take and generate captions from the final audio timing.

The model ID and speech guidance were checked against [ElevenLabs models](https://elevenlabs.io/docs/overview/models) and [Eleven v4 prompting guidance](https://elevenlabs.io/docs/overview/capabilities/text-to-speech/best-practices).

## Raw-demo preparation

1. Use the current Home hero and workflow, then the saved views above. Record one deliberate screen walkthrough at the intended final frame size, with legible text and a quiet pointer.
2. Preload the selected recordings, image proposal and candidate screenshots. Keep the selected round stable. Prepare any local summary using real supplied observations; inspect the result before it appears in the take.
3. Move while speaking. Show the reaction and price at the words that explain them. Use the app's condensed recording for the journey and original, explicitly aligned recordings for the retest.
4. Keep API waits, credentials, setup dialogs, long lists and operational configuration out of the three-minute picture. The recording label must remain clear; completed model runs are not portrayed as instantaneous live inference.
5. Hold the actual code view long enough to register its existence, then return to the implemented result. Keep review status visible.
6. If the raw take exceeds a beat, shorten the navigation or optional local-analysis dwell first. Preserve the product definition, model roles, working code, paired result and synthetic-scope sentence.
7. At the final-edit stage, add only useful captions: model names beside their actual roles; CAD amounts; **Maya 10 → 5 / Alex 6 → 6 recorded actions** during the exact pair; and the hackathon-contribution caption.
