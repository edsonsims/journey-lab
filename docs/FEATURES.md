# Journey Lab features

Open **http://127.0.0.1:4319/**. Journey Lab supports multiple local product projects, real recorded journeys, source-linked findings, isolated Muse Code fixes, review and retesting. The workspace opens on **Home**, with a general Journey Lab introduction and the live project list. Opening or switching an app leads to **Journeys**. Its **Overview** remains available in Settings. The sidebar keeps **Journeys**, **Insights**, and **Library** at the top, with **Settings** anchored at the bottom. **Overview** lives inside Settings alongside Gather’s **Guided example**, clearly labeled as a fictional product inside Journey Lab. Project overviews use that project’s live records for review priorities, journey outcomes, recent recordings, persona activity, setup, and reported usage. `/legacy` and the recorded film at `/demo.html` remain available.

Build the interface before starting the engine:

```sh
npm --prefix journey-workspace install
npm --prefix journey-workspace run build
npm --prefix journey-engine install
```

Start LittleSteps on port 4320, then run the engine from its own directory:

```sh
cd journey-engine
JOURNEY_SHOW_BROWSER=1 npm run start:secure
```

The secure launcher delegates access to the existing 1Password `.env` mount without reading or logging the key itself. If 1Password has not released the mount within ten seconds, it terminates that blocked startup and opens the app in review mode. Unlock/approve 1Password, stop the review server, and run the same command to enable Meta. `npm start` uses the current process environment and also supports review without a key. Do not copy secrets into source, logs or chat.

- **Home:** `/` opens the centered Journey Lab introduction with six persona cards linking directly to their saved Gather profiles. The four illustrated steps cover persona, mission, journey with evidence, and improvement, with prominent top-left numbers and model roles: Muse Voice Transcribe captures spoken briefs, Muse Wonder drafts personas and missions, then explores the app, Muse Glimmer supports local text analysis, Muse Image proposes visual designs, and Muse Code implements candidates for Wonder retests. An expandable explanation identifies all five models and explains the optional voice, local-analysis, and design tools. The former Home v1/v2 routes and version switch are retired; old `?home=` links show the current Home.
- **Project overview:** `/projects/<project-id>/dashboard` leads with goal attainment, journeys with friction, open high-impact findings and candidates awaiting review. Activity, outcomes, personas, severity and the fix pipeline link to recorded evidence. Metrics are scoped to loaded eligible journeys; experimental and invalidated evidence is excluded, missing usage remains unknown, and approval stays separate from deployment or issue resolution.
- **Gather guided example:** `/projects/gather/guide` has its own hero and six connected stops: change, people, price and fix, name and fix, candidate and retest. A broad serpentine path wraps around staggered scenes, then becomes a single reading trail on mobile. Each problem sits beside its fix at matching zoom: Atlas’s room rate versus its full total at selection, and the empty versus preserved meeting-name field after changing rooms. Both Atlas versions cost the same; the candidate shows the total earlier. Full source screens and paired journey traces are available in disclosures; the retest switch focuses on the final total. The saved room-change check is labeled scripted QA and requires its exact candidate and round, separately from persona recordings. The story explains the fictional booking product, Quick booking and the Muse Code candidate. Persona briefs, paired journeys, original video moments, candidate review and the captioned film link to their source evidence. Historical outcome claims and frames require their exact eligible demo sessions; proposal comparisons and fresh candidate retests remain distinct. Named `?chapter=` links address each stop; legacy `dashboard?view=story&step=N` links retain their corresponding destinations, while `view=workspace` opens the project overview.
- **Journeys:** compact attention-first history, smart filters, impact counts, provider usage, original/condensed recordings, four event tracks and Emotional Arc. Run details align a compact video with the frame-by-frame tracks and emotional arc on desktop. A shared card below them shows the full AI Persona reaction alongside the recorded context. Clicking a track marker pauses the recording and puts that exact event or finding’s text in the card; resuming playback follows the current reaction again. Finding selections also survive refreshing a source-moment link. The Moments tab retains the observation list; smaller screens stack the evidence. Large histories load in pages with their scope displayed.
- **Findings, Issues and Fixes:** source moments, actual navigation/input context, technical evidence, review history, grouped defects, isolated implementation rounds, annotations and independent retests. Findings share the run review layout: video and synchronized charts above a compact AI Persona reaction card. Explore this recording with Meta opens below the recording in both findings and runs. Finding details retain the fix action below the recording area without the triage or recurring-issue cards. Before/after emotions can be aligned by suggested or reviewed steps, including drag matching with frame/comment previews.
- **Memory:** automatic source-backed publication with confidence and its basis; immutable versions, conflicts, corrections and archive. First-time personas get no prior persona learning. Returning personas require a mission that enables eligible knowledge. Screen access is recorded; active runs and fix comparisons retain their pinned snapshots. Experimental knowledge stays isolated.
- **Insights:** versioned screen inventories, honest coverage denominators, contextual screen experience, exact source-video links, separate AI/reviewer friction scores and frozen reports. Experience details place an interactive emotional arc directly below the video or screenshot, with previous/next moment controls and a “What happened” observation beside it. The arc replaces the separate screen filter and reaction list; its controls also reach unrated and untimed moments. Selecting an arc point updates the evidence without jumping the scroll position; both columns share one scroll area, and compact screens stack the content. An **Open moment in journey** action opens the original recording with the exact source reaction selected. A coverage gap can prepare an unsaved mission. Experimental and invalidated observations are excluded from ordinary product aggregates.
- **Change impact:** local proposals, supplied proposed/merged PR origins and labeled illustrative examples share one compact list and `/impact/<id>` detail layout. Persona links open the relevant perspective directly; examples stay excluded from recorded assessment totals. Each detail places the selected person’s paired videos on the left and a compact perspective list on the right, with one full-width “Did it feel better?” arc directly beneath the videos. The video height adapts to the window; Expand videos enlarges both in place. The arc follows each original recording’s current observation with distinct highlights and source timestamps. Generous dot targets resolve by distance rather than paint order; overlapping before/after moments offer a choice. Side-by-side before/after lists below the chart include every feeling, including untimed and unrated reactions, with larger text and fully wrapped reactions. Both lists expand to show every reaction in the normal page flow, with no nested scroll areas; selecting a feeling seeks the source moment without jumping the page. The wider perspective rail shows explicit goal outcomes, before/after actions and negative-reaction counts, and concise count-change takeaways. Matched-tone counts use plain-language labels. Overlay is the default shared scale; Layers brings the selected persona forward. The selected person’s before and after arcs appear together on the foreground plane: dashed slate before, solid purple after. Other people’s paired arcs remain faded behind them, and green, gray, amber and pink bands identify reaction tone. The overview uses observation progress, not matched actions or elapsed time; missing ratings and times leave gaps. Each version has observation controls. Clicking an arc moment seeks the selected person’s original before/after videos above at the same elapsed time, or at the current explicit alignment. Missing timestamps and exhausted recordings are shown without inventing a matching frame. The selected-person evidence section stays alongside the perspective list at ordinary panel widths, regardless of perspective count. Recorded sides show videos and reactions; illustrative examples show paired scenario summaries and the selected reactions, explicitly stating that no recording exists. Both use the same evidence component with no second emotional chart; step-match review and drag alignment remain available below recordings. Matched-action tone comparisons exclude unmatched observations; divergent negative moments remain inspectable. Source dates remain separate from assessment dates, and source details and change summaries are versioned.
- **Library:** manual and Meta-assisted persona/mission authoring, saved versions, selectable Memory, supplied competitor profiles and exact source excerpts. Public research is bounded and creates unreviewed claims; comparisons retain context and uncertainty.
- **Calibration:** read-only local event imports, behavior mappings, frozen studies, bounded persona-context candidates, repeated development/held-out trials and exact-result adoption review.
- **Settings:** Anchored at the bottom of the sidebar, with Devices first, followed by Environments, Network profiles, Connections, App overview and (for Gather) Guided example. Gather’s standalone Watch demo button and page have been removed; the guided example retains its recorded film. Personas can have several devices with one primary; each journey freezes its device and connection settings. Hover or focus a device badge to inspect recorded settings. See [Devices and network profiles](DEVICE_PROFILES.md).
- **Environments and Connections:** configured development/staging/production targets, versioned origins/source/build/start/test/session settings, budgets, data policy and readiness checks. Temporary test and fix instances belong to their configured environment and shut down after use. Connections describes the Meta models and integration setup.

Records live in `journey-engine/workspace-data/`, including the workspace SQLite database, Calibration database and isolated fix workspaces. Original recordings remain in `journey-engine/runs/`. Retention is keep-all. Back up the entire data directories together; see the [release runbook](RELEASE_RUNBOOK.md).

Git contains application source, fixtures, tests and documentation. Credentials, local databases, run evidence, generated demo media and temporary workspaces are excluded. A fresh clone starts without this machine's history or recorded demo films; the historical results below refer to retained local artifacts.

Actual draft-PR delivery still needs a selected source-code provider/repository and approval of the exact candidate. Real analytics validation needs a compatible real import. Competitor research needs user-supplied targets. These are explicit setup gates, not simulated integrations.

Verification and current limitations: [release status](RELEASE_STATUS.md), [runtime checks](RUNTIME_RELEASE_CHECKS.md), [implementation plan](IMPLEMENTATION_PLAN.md). The historical demo/results below remain tied to their original recordings and dates.
